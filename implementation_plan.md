# Архитектурный план: Переход на динамическое управление городами и ставками зарплат

Этот документ описывает техническое проектирование и пошаговый план перехода от жестко захардкоженных городов (Минск и Гомель) к гибкой системе динамического управления городами и тарифными ставками фотографов напрямую из админ-панели Telegram-бота.

---

## 1. Проектирование Базы Данных (БД)

Для реализации динамического подхода мы заменим статические списки и константы двумя новыми таблицами в БД: `cities` и `salary_rules`.

### Таблица `City` (Модель `City`)
Хранит общую конфигурацию для каждого города.
* `id`: `Integer`, `primary_key=True`
* `slug`: `String(20)`, `unique=True`, `index=True` — внутренний строковый идентификатор города (например, `'brest'`, `'gomel'`).
* `name`: `String(100)` — красивое отображаемое имя города на русском (например, `'Брест'`).
* `emoji`: `String(10)` — эмодзи для отображения в кнопках и отчетах (например, `'🏙️'`, `'🌆'`, `'🌉'`).
* `thread_id`: `BigInteger`, `nullable=True` — ID Telegram Forum Thread (топика) для пересылки отчетов данного города.
* `is_active`: `Boolean`, `default=True` — статус активности. Отключенные города не выводятся в клавиатурах для отправки отчетов.

### Таблица `SalaryRule` (Модель `SalaryRule`)
Хранит тарифную сетку для фотографов каждого города. Позволяет гибко воспроизвести любые правила: как по дням недели (Гомель), так и общие / по сменам (Минск).
* `id`: `Integer`, `primary_key=True`
* `city_id`: `Integer`, `ForeignKey("cities.id", ondelete="CASCADE")` — связь с городом.
* `day_type`: `String(20)` — тип дня, для которого применяется тариф:
  * `'all_days'` — для всех дней (как в Минске).
  * `'weekday'` — будни Пн–Пт.
  * `'saturday'` — суббота Сб.
  * `'sunday'` — воскресенье Вс.
* `shift_type`: `String(20)`, `default='full'` — тип смены: `'full'` (полная смена) или `'half'` (половина смены, как в Минске).
* `threshold_min`: `Float` — минимальный порог выручки (например, `0.0`, `200.0`, `300.0`).
* `threshold_max`: `Float`, `nullable=True` — максимальный порог выручки (не включительно, `None` — безлимитно).
* `base_salary`: `Float` — фиксированный оклад за смену при попадании в этот диапазон.
* `percentage`: `Float` — процент от выручки при попадании в диапазон (например, `0.10` для 10%).

## 2. Пользовательский интерфейс Администратора (UI/UX в Telegram)

В главном меню админа (`kb_admin_main`) появится раздел **«🏙️ Города»** (callback: `adm:cities`).

### Меню управления городами:
1. **Список городов**: Показывает все города в базе с их эмодзи и активным статусом.
2. **Кнопка «➕ Добавить город»**: запускает FSM-сценарий создания города.

### FSM Сценарий добавления города:
1. **Шаг 1**: Введите красивое название города (например: `Брест`).
2. **Шаг 2**: Введите slug-идентификатор латиницей (например: `brest`).
3. **Шаг 3**: Введите эмодзи для кнопок (например: `🌉`).
4. **Шаг 4**: Введите ID Telegram-топика (Thread ID) для отчетов или `0`, если топик не используется.
5. **Шаг 5 (Выбор шаблона тарифов)**:
   Админу предлагается выбрать пресет для инициализации тарифов:
   * **«Пресет Гомеля»** (Создает правила отдельно для будней, Сб, Вс с базой 25р + 10% на младшем пороге).
   * **«Пресет Минска»** (Создает общие правила на все дни для полной смены с базой 45р и полусмены с базой 22.5р).
   * **«Пустой тариф»** (Создает пустую сетку для настройки с нуля).

### Управление городом (Профиль города):
Админ выбирает город из списка и видит его настройки:
* Название: *Брест*
* Статус: *Активен / Неактивен* (кнопка переключения `city:toggle:<id>`)
* Топик ID: *123456*
* **Кнопки управления**:
  * `📝 Редактировать инфо` (изменить название, эмодзи, топик).
  * `📊 Тарифная сетка ЗП` (переход в меню настройки ставок).
  * `❌ Удалить город` (с каскадным удалением правил).

### Интерфейс настройки ставок/тарифов ЗП (`SalaryRules`):
Показывает текущую тарифную сетку города. Например:
> 📊 **Тарифы для г. Брест (Пн-Пт)**:
> 1. `0 - 200 р` ➔ Оклад `25 р` + `10%`
> 2. `200 - 300 р` ➔ Оклад `0 р` + `20%`
> 3. `300 - ~ р` ➔ Оклад `0 р` + `22%`
>
> ➕ Добавить диапазон | 🔄 Изменить тип сетки (По дням / Общая)

При клике на диапазон админ может:
* Изменить его пороги, оклад и процент одной строкой ввода (как это сейчас реализовано для менеджера).
* Удалить диапазон.

## 3. Модификация клавиатур на динамические

Все функции в [builders.py](file:///F:/ph-time-tg/bot/keyboards/builders.py) будут переписаны с асинхронным получением списка городов из сессии БД.

```python
# Пример рефакторинга kb_city
async def kb_city(session: AsyncSession) -> InlineKeyboardMarkup:
    """Генерирует клавиатуру на основе активных городов из базы данных."""
    res = await session.execute(select(City).where(City.is_active == True).order_by(City.name))
    cities = res.scalars().all()
    
    b = InlineKeyboardBuilder()
    for city in cities:
        b.button(text=f"{city.emoji} {city.name}", callback_data=f"report:city:{city.slug}")
    b.button(text="❌ Отмена", callback_data="report:cancel")
    b.adjust(2, 1)
    return b.as_markup()
```

Аналогично будут переведены на БД-генерацию:
* `kb_city_for_employee` (выбор города для привязки к сотруднику).
* `kb_city_selector` (выбор города в личном кабинете).
* `kb_analytics_cities` (список городов в графиках аналитики).
* `kb_monthly_report_cities` (список городов для генерации Excel-календаря).
* `kb_employee_cities` (фильтрация списка сотрудников).

## 4. Динамический расчет зарплаты (`bot/utils/salary.py`)

Мы полностью перепишем расчет зарплаты фотографов. Больше никаких жестко зашитых списков `_GOMEL_WEEKDAY` и `_MINSK_ALL`.

### Новая логика `calculate_photographer_salary`:
1. Находим в БД правила `SalaryRule` для данного `city_slug`.
2. Определяем `day_type`:
   * Если в правилах города есть `'all_days'`, используем его.
   * Иначе определяем тип текущего дня по дате (`weekday`, `saturday`, `sunday`) и берем соответствующие правила.
3. Добавляем поддержку полной/половинной смены (`shift_type`):
   * Если у сотрудника полусмена (выбирается при отправке отчета), берем правила с `shift_type == 'half'`.
4. Находим нужный интервал `threshold_min <= revenue < threshold_max` и рассчитываем ЗП:
   $$Зарплата = \frac{base\_salary + (revenue \times percentage)}{shift\_count}$$

## 6. Рефакторинг текстовых меток (Labels)

Все сопоставления вида `{"gomel": "🏙️ Гомель", "minsk": "🌆 Минск"}` будут заменены на динамическое получение красивой строки:
```python
async def get_city_label(session: AsyncSession, slug: str) -> str:
    res = await session.execute(select(City).where(City.slug == slug))
    c = res.scalar_one_or_none()
    return f"{c.emoji} {c.name}" if c else slug.title()
```
Для высокой производительности мы добавим локальный кэш названий городов в памяти, чтобы не делать лишних запросов к БД при генерации списков сотрудников или отчетов.
